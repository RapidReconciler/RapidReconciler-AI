Blank or missing data

User sees no data after login

You can sign in, but the page is blank or shows no figures. The cause is almost always something on your network, browser, or VPN — or, if your RapidReconciler server was recently moved, a new IP that RR support needs to register. The steps below resolve most cases without contacting support.

What you’re seeing

  • You log in successfully, but the Reconciliation, Inventory, or other pages are empty.
  • The screen shows “I see no data,” “the page is blank,” or “everything is empty.”
  • Everyone suddenly sees no data right after the RapidReconciler server was moved, rebuilt, or had its IP changed — logins still work, but every page is empty. That has a specific cause; see the box below before working the steps.
  • Common phrasings: “blank screen on my laptop,” “works for everyone else but me,” “logs in fine on a different computer,” “no data since we moved the server.”

First: did your RR server just move or change IP?

Recently moved the RR server, or its IP changed? Start here For your IT / admin
When this applies: the RapidReconciler server was moved, rebuilt, or its public / outbound IP changed, and now everyone can log in but no data loads. If nothing changed on your side, skip to the steps below.

RapidReconciler reaches your data over a connection keyed to your server’s network address. When the server moves or its public IP changes, that address no longer matches what’s on file — sign-in still succeeds (that’s a separate path), but every data call comes back empty until the new address is registered.

To get data flowing again:

  1. Send RR support your new public (outbound) IP address so we can update the allow-list on our side. This is the most common fix — and a step only RR support can complete.
  2. Confirm the database host and named-instance port are unchanged. If the SQL Server host name or port is different on the new server, send the updated values too.
  3. Give it a few minutes after we confirm the update, then reload RapidReconciler.

Try these steps in order

Step 1
Check your bookmark URL
When this applies: always check this first — it’s a 30-second test and a common cause of blank pages.

Your bookmark must point to rapidreconciler-prod.getgsi.com — the root URL, not a saved deep link to the Reconciliation page or any other inner page.

Why it matters: if your bookmark goes straight to a deep page and your network password has expired, the redirect to the login prompt can fail silently. You see a blank page and assume RapidReconciler is down, but the real issue is that you never reached the login screen.

  • Open your bookmark and look at the URL bar. If it shows anything past rapidreconciler-prod.getgsi.com (a longer path, a query string, an anchor), edit the bookmark to point at the root URL.
  • Re-open the bookmark. You should land on the login screen.
  • If you land on the login screen and your sign-in is rejected, your password has likely expired — reset it the way you normally would for your corporate account, then sign in.
Data appears after sign-in? Stop here. Otherwise, continue to Step 2.
Step 2
Confirm you’re on VPN or the corporate network
When this applies: you’re working remotely — from home, while travelling, or off-site.

RapidReconciler is only reachable from your corporate network or via your organization’s VPN. If you’re disconnected, login can succeed but no data will flow.

  • If you’re working remotely, confirm you’re connected to your organization’s VPN or approved remote-access method.
  • If you believe you’re connected, disconnect and reconnect the VPN, then hard-refresh the browser.
Resolved? Stop here. Otherwise, continue to Step 3.
Step 3
Allow local-network access in your browser
When this applies: your browser was recently updated, or this is a new workstation.

Edge and Chrome have a permission gate that controls whether sites can connect to local-network devices. If RapidReconciler isn’t on the allowed list, all data calls silently fail.

Both browsers call it Local network. Only the route to reach it differs.

Microsoft Edge:

  • Open Settings → Privacy, search, and services → Site permissions → All permissions → Local network.
  • Leave Default behavior on Ask before accessing (recommended).
  • Under Customized behaviors, verify rapidreconciler-prod.getgsi.com is in the Allowed to access other devices on your local network block — the lower of the two.
  • If it’s missing, click Add site beside that block and add it.
  • If it’s in the Not allowed block above instead, remove it from there first — a block entry wins, and the prompt won’t come back on its own.

Google Chrome:

  • Open Settings, type local network into the search box, and open Local network. The full path is Privacy and security → Site settings → Permissions → Additional permissions → Local network.
  • Same two blocks, same wording, same Add site button as Edge.
  • Don’t pick Apps on device. It sits directly beside Local network in Chrome’s list and governs something else entirely — access to other apps on the same machine. Granting it changes nothing here.

Then hard-reload the page and check whether data appears.

If you can’t find or change the setting on your machine, ask your IT department to adjust it.

Resolved? Stop here. Otherwise, continue to Step 4.

Step 5
Look for a blocked connection in your browser
When this applies: Step 4 showed it’s just you, or only some people. Worth thirty seconds even if you’re not technical.

This looks for one specific cause: your account not being allowed to reach RapidReconciler through your company’s access service. If that’s what it is, nothing you can change will fix it — but the line below tells your IT exactly what to do, which turns a long investigation into a five-minute change.

  1. With RapidReconciler open, press F12.
  2. Click the Console tab in the panel that opens.
  3. Reload the page with Shift + F5.
  4. Look for a red line naming your own RapidReconciler address followed by a colon and a five-digit number.

It looks like this:

If you see that line, send this to IT

Copy the whole red line, and send it with this sentence:

“Please grant my account access to the RapidReconciler application segment in Zscaler. The connection to this address and port is timing out.”

This was the fix at two other companies. It is a permissions change on their side — not a fault in RapidReconciler, and not something you can set yourself.

If the console is empty, or shows something different, this isn’t your cause. Continue to Step 6.

Found that line? Send it to IT and stop here. Otherwise, continue to Step 6.
